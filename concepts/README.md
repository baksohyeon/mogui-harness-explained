# Concepts

Eight short notes on the ideas behind the units, each written for a reader who has never run the harness, followed by the house rules for a master's chat replies and a glossary. Each note answers the same five questions: what happened, what is confirmed, what is inferred, what is unknown, and where the evidence is. The glossary defines the words the notes use without stopping to explain them. Every evidence link points at the public repository at tag `v0.5.288`.

| Note | One line |
|---|---|
| [Orca primer](orca-primer.md) | Orca owns terminals, worktrees, and the mailbox; the harness decides what goes in and proves it arrived. |
| [Role lock](role-lock.md) | The master proposes and verifies; workers write code; a hook enforces it. |
| [Fail closed](fail-closed.md) | A gate that cannot decide stops the work; exit 2 is never a pass. |
| [Measured, confirmed, inferred](measured-not-assumed.md) | Every claim says how it was obtained. |
| [Worker territory](worker-territory.md) | One checkout, one contract, by default a different runtime, and a read token. |
| [Template and seat](template-and-seat.md) | One upstream, many installs, upgrades against a manifest. |
| [Succession](succession.md) | Generations of masters, placement proof, three measured disappearances. |
| [Charter map](charter-map.md) | Ten numbered sections; which one owns which decision. |
| [Chat response rules](chat-response-rules.md) | Twelve sentence rules for replies to the owner, most derived from ASD-STE100. |
| [Glossary](glossary.md) | Ninety-two entries for the words the unit, concept, and walkthrough pages use, one line each, with where to read more. |
